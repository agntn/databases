The CLI takes a database reference or a connection name. Start with `providers` to see what your process knows.

```bash
databases providers
```

```text
3 engines:
sqlite  SQLite
  reference: sqlite:<path>, or a path ending in .db, .sqlite or .sqlite3
  read-only: file opened read-only, and SQLite's authorizer denies every action but a read while the statement is prepared
postgres  Postgres
  reference: postgres://user:password@host:5432/database
  read-only: a READ ONLY transaction with a statement timeout, over the extended protocol, which takes one statement
d1  Cloudflare D1
  reference: d1:<database name or id>, or d1://<account id>/<database>
  read-only: the statement is prepared against an empty copy of the remote schema under SQLite's authorizer before it is sent
  credentials: CLOUDFLARE_API_TOKEN, or the cf CLI's login; the account from CLOUDFLARE_ACCOUNT_ID or the login
1 connection, pass the name as database:
shop  postgres  postgres://reader:***@127.0.0.1:54329/shop
Writes: off, databases_execute refuses. Set DATABASES_WRITE=1 for the server to allow it.
```

That command does not connect to a database. Why start there? It lists the connection names you can pass.

## Which command does the job?

- `providers` lists engines, named connections and the write switch.
- `schema <database> [table]` lists tables and views, or describes one.
- `sample <database> <table> [-n]` reads rows without SQL.
- `query <database> <sql> [--params JSON] [-n/--limit]` runs one read-only statement.
- `explain <database> <sql> [--params]` returns a plan without running the statement.
- `execute <database> <sql> [--params]` runs one statement that may write.
- `mcp` starts the MCP server.

Pass `--params` as a JSON array. Use `-n` or `--limit` to set the row limit. A query defaults to 50 rows and a sample to 10. Both allow up to 1000.

Use `--json` on any command for a structured result. Pass `-` as SQL to read it from standard input.

```bash
echo 'SELECT count(*) FROM Track' | databases query chinook.db -
```

Use `--help` to see command help.

## What happens when a call fails?

A refusal or failure exits with code 1. It prints one line on standard error, ending in `[code]`.

```bash
databases execute shop "DELETE FROM orders"
```

```text
Writes are off on this server, so nothing ran. Ask the user to start it with DATABASES_WRITE=1 if the change is wanted. [refused]
```

That refusal is a feature, not an inconvenience. An agent itching to type DELETE still needs permission. See [read only](/guide/read-only) before enabling writes.
