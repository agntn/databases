Import `open` and give it a database reference. The returned provider exposes methods for inspecting and querying it.

```ts [count.ts]
import { open } from "@agntn/databases";

const db = await open("sqlite:./chinook.db");
const result = await db.query("SELECT count(*) FROM Track");
console.log(result.columns, result.rows);
```

```text
[ { name: 'count(*)' } ] [ [ 3503 ] ]
```

A relative file depends on your working directory. That detail matters more than the filename looks.

## Which method should you use?

- `tables()` lists tables and views.
- `table(name)` describes columns, indexes and foreign keys.
- `query(sql, { params, limit, signal })` runs a read-only statement.
- `sample(table, { limit })` reads the first rows without SQL.
- `explain(sql, { params })` returns a plan as `{ lines }`.
- `execute(sql, { params })` runs one statement that may write.

A sample has no defined order, so Iron Maiden gets no guaranteed place.

## What comes back from a query?

The result is `{ columns, rows, more, cut }`. Each column is `{ name, type? }`, and each row is an array of cells. `more` means the row limit cut the result. `cut` means values or rows were shortened.

Text over 500 characters ends with `… [+N chars]`. A blob is `{ "$blob": "<hex of first 32 bytes>", "bytes": <size>, "cut": true when longer }`. Integers past 2^53 are exact strings where the engine preserves them. Dates are ISO strings, and Postgres numeric values are exact strings.

The answer keeps rows while their JSON stays under about 100000 characters. It includes at least one row. D1 has a precision exception described in its [engine guide](/providers/d1).

`execute` returns `{ changes, lastInsertId? }`.

## How do you read a whole SQLite file?

Need the data itself, not a sample for an agent? A cut cell saves context for an agent but damages a transcript. Agents get budgets. Programs can get whole values.

```ts [export.ts]
import { read } from "@agntn/databases/sqlite";

const since = Date.now() - 86_400_000;
const { rows, more } = await read("./sessions.db", {
  sql: "SELECT id, data FROM part WHERE time_created > ? ORDER BY time_created",
  params: [since],
  limit: 5000,
});
```

`read` returns `columns`, `rows`, and `more`. Text comes back uncut, blobs as `Uint8Array` bytes, and integers past 2^53 as `bigint`. Other integers come back as `number`. There's no cell budget, answer budget, or `cut` flag.

Pass a SQLite path, `sqlite:<path>`, or a connection name set to a SQLite file. Postgres and D1 are refused with code `config`. The file opens read-only, and SQLite's authorizer guards each statement. Each call accepts one statement. Writes are refused with code `refused`, and a missing file isn't created.

Without `limit`, you'll get every row. Set it to any positive integer to cap the rows. `more` is true when rows past that limit were left unread. There's no deadline unless you set `timeoutMs`. You can also pass a `signal` to abort.

On Node, `read` runs in the calling process. Without `node:sqlite`, it runs in a Node child process. In process, deadlines and signals are checked every few hundred rows. A long SQLite step, such as a sort before the first row, must finish first. Agent tools keep their existing limits. `read` is library only, with no tool for it.

## How do you handle errors and extensions?

A `DatabasesError` has `code`, `provider` and `engineCode`. Codes are `config`, `auth`, `connection`, `refused`, `query`, `timeout` and `unsupported`. In Postgres, `engineCode` can contain a SQLSTATE such as `42P01`.

For schema changes, `applyMigrations(db, { directory })` runs a folder of `.sql` files. The [migrations guide](/guide/migrations) has the rest.

For another provider, extend `Provider` and register it with `register(meta, ProviderClass)`. The package also exports `parseReference(reference)`, `listConnections()`, `listProviders()`, `providers()` and `create(target)`.
