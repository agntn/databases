Why type a password into a chat at all? A connection name keeps the URL out of your prompts. Put its reference in the process environment, then pass the name.

## Which references work?

- SQLite accepts `sqlite:<path>`, a `file://` URL, or a recognized path.
- Postgres accepts a `postgres://` or `postgresql://` URL.
- D1 accepts `d1:<name or id>` or `d1://<account id>/<database>`.

A SQLite path is recognized when it starts with `/`, `./`, `../` or `~/`. A path ending in `.db`, `.db3`, `.sqlite` or `.sqlite3` also works.

A bare name looks up an environment variable. For `shop-prod`, that variable is `DATABASES_SHOP_PROD_URL`. The name becomes uppercase and hyphens become underscores. An unknown name reports the expected variable and configured names.

## Will the answer expose a password?

Answer labels hide the password and sensitive query parameters. Parameter names containing `pass`, `secret`, `token` or `key` are redacted.

```bash
databases schema shop
```

```text
postgres://reader:***@127.0.0.1:54329/shop (postgres): 3 tables and views
public.big_orders  view
public.customers  table
public.orders  table
Pass one as table for its columns, indexes and keys.
```

Redaction is not permission to paste credentials into transcripts. A password in a prompt can still travel elsewhere.

## Where does a relative path start?

The process working directory determines its absolute path. For an MCP server, give SQLite an absolute path. Guessing where a server starts is a bad plan.

## What does D1 need?

Set `CLOUDFLARE_API_TOKEN`, or use the `cf` CLI login. The account comes from `CLOUDFLARE_ACCOUNT_ID` or that login. A `d1://` reference includes a 32 character hexadecimal account ID.

See [D1](/providers/d1) for name lookup and token behavior.
