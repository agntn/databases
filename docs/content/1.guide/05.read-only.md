A read must not quietly turn into a write. Each engine enforces that boundary differently.

## What happens in SQLite?

SQLite opens the file read-only and installs an authorizer. The authorizer checks actions while the statement is prepared. It allows SELECT, column reads, recursive CTEs and safe functions. It refuses `load_extension` and certain functions that touch files.

Read-only pragmas are allowed, including `table_info`, `index_list`, `foreign_key_list` and `integrity_check`. `user_version` is allowed without a value. A setting pragma, ATTACH, BEGIN or a write inside a CTE is refused.

VACUUM is refused by its first word. SQLite otherwise asks the authorizer about it only during execution.

So what does turning foreign keys off get you?

```bash
databases query chinook.db "PRAGMA foreign_keys = off"
```

```text
Refused: the statement writes, changes a setting, attaches a file or calls a function outside the database. Only reads run here; use execute for a write [refused]
```

## What happens in Postgres?

The session starts with `default_transaction_read_only`. Each read runs in `BEGIN READ ONLY`, with a `statement_timeout` of 30 seconds set for that transaction only. The extended protocol refuses a second command in the same string.

A read-only transaction is not a complete privilege boundary. Some functions have side effects without needing a write. `pg_terminate_backend` is one example, subject to role privileges. Use a role with only SELECT permissions.

## What happens in D1?

Before sending a read, the package fetches the schema. It caches the CREATE statements for one minute. A child process prepares the statement against an empty schema copy. It uses the same SQLite authorizer described above.

A write, second statement or schema mismatch is refused locally. The refused statement never reaches D1.

## Can a second statement sneak through?

No. After the first statement, only comments and semicolons are allowed.

```bash
databases query chinook.db "SELECT 1; DROP TABLE Track"
```

```text
Refused: send one statement per call. Everything after the first `;` would have run too [refused]
```


## How do you write on purpose?

Use `databases_execute` or the `execute` command. Both check `DATABASES_WRITE=1` in their process before running. Postgres executes the statement in its own transaction. An agent that wants to delete the catalog cannot bypass that switch through a read.

```bash
DATABASES_WRITE=1 databases execute scratch.db "UPDATE Genre SET Name = ? WHERE GenreId = ?" --params '["Heavy Metal", 3]'
```

```text
/var/tmp/chinook/scratch.db (sqlite): 1 row changed
```

## What can a read still reveal?

Read access can expose everything your database role can read. Use the smallest appropriate permissions and avoid putting secrets in query results.

SQLite child processes are killed after 30 seconds or on abort. Postgres uses the 30 second statement timeout. Query results default to 50 rows, with a maximum of 1000. Samples default to 10 rows, with the same maximum. Long values and large answers can be shortened, as described in the [library guide](/guide/library).
