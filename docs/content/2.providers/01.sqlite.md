Point SQLite at a file that already exists. A missing file is refused, not created.

::provider-roster{engine="sqlite"}
::

## How do you name the file?

Use `sqlite:<path>`, a `file://` URL, or a recognized path. Paths starting with `/`, `./`, `../` or `~/` work. So do paths ending in `.db`, `.db3`, `.sqlite` or `.sqlite3`.

Relative paths resolve against the process working directory. For MCP, use an absolute path instead. Why not just create it? A typo would hand the agent an empty music store that answers every question with nothing.

## Why can't a read write?

The file opens read-only and SQLite's authorizer checks the statement. It allows reads and refuses writes during preparation. It also refuses actions such as ATTACH and setting pragmas. VACUUM is refused by its first word.

Every call runs in a fresh Node child process. Its environment contains only `PATH`. The child is killed after 30 seconds or on caller abort. Under Bun hosts, it uses `node` from `PATH`.

This boundary is worth understanding, not merely trusting. See [read only](/guide/read-only) for the detailed rules.

## How are values represented?

Boolean parameters bind as `1` and `0`. Big integers are preserved exactly as strings when needed. Blobs report their size and the first 32 bytes as hex. A blob longer than that is marked as cut.
